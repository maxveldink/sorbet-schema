# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- Add durable project-specific notes here as they are discovered through real work.
- Ruby 3.4+ unbundles former stdlib gems (e.g. `csv`) from the default load path, so `require "csv"` is not free — it needs the gem actually installed.
- Format-specific serializers (`CSVSerializer`, `MessagePackSerializer`, `ActiveRecordSerializer`) are meant to treat their backing gem as optional: no top-level `require`, gem is `add_development_dependency` only (not `add_runtime_dependency`), the `require`/gem-presence check happens lazily in `initialize` with a clear `ArgumentError` on failure, and `T::Struct.serializer`'s factory (`lib/sorbet-schema/t/struct.rb`) mirrors that same guard via `defined?(...)`. Follow this pattern for any new serializer/coercer with a non-stdlib dependency; see `lib/typed/csv_serializer.rb` for the exact shape. **`ActiveRecordSerializer` does not actually follow it yet** — `lib/typed/active_record_serializer.rb` references `ActiveRecord::Base` directly in its `type_member`/sig declarations at class-body load time (no lazy `require`/`rescue LoadError`), so any Zeitwerk-forced eager load of the class (e.g. `bundle exec tapioca gem` in a consumer that lacks the `activerecord` gem, even one that never touches `:activerecord` serialization) raises `NameError: uninitialized constant ActiveRecord` rather than a clean error. Discovered as a side effect of downstream-consumer verification for the issue #89 generics work, not introduced by it, and still unfixed — worth a dedicated fix following the CSV/MessagePack shape.
- Every `Typed::Serializer` subclass (all six format serializers) and `Typed::Schema` are generic over the struct type via a `StructT = type_member { {upper: T::Struct} }` re-declared in each subclass — this is what lets every deserialize path (`deserialize_from`, `.serializer(:x).deserialize`, `.schema.from_x`, direct serializer construction) return the concrete struct type with no `T.cast`. `Typed::Schema#target`'s type is `T.all(T::Class[StructT], T.class_of(T::Struct))`, not the more obvious bare `T::Class[StructT]` — sorbet-runtime erases `T::Class[X]` to `T::Class[T.untyped]` at runtime, silently accepting a non-struct target; the intersection restores the runtime check. See `lib/typed/serializer.rb`, `lib/typed/schema.rb`, and `lib/typed/hash_serializer.rb`'s `self.new` override (the one class that needs it, for direct-construction type inference) for the exact shape when adding a new serializer.
- After adding a new *required* runtime gem dependency (not this optional-serializer case), run `bundle exec tapioca gem` (add the gem to `sorbet/tapioca/require.rb` first if it isn't required anywhere else) so `bundle exec rake` (which runs `srb tc`) has an RBI to check against.
